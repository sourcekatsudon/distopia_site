# 施設と遭遇の再設計 — 2026-11-19

## 改修方針

前回の均等なネオン線と光輪中心の構図を改め、近景の機械、中景の支配者／敵／遮蔽物、遠景の設備を分ける。武器の造形・自動/Rセル交換は維持し、今回は空間、照明、遭遇を中心に変更した。

## 支配者

玉座を新しい `ruler.js` に全面置換。球状の胸コアと同心円の光輪を撤去し、縦型の炉、分割胸装甲、不揃いな放熱冠、ピストン、長い腕と個別の鉤爪で構成した。電源ラック式の玉座、ケーブル束、奥へ続く柱とサーバー、手前で画面に切れる設備を配置。低い視点から55度の画角でゆっくり接近する。

プレイヤー用ライトが断罪シーンも照らして白く潰していたため、玉座中は無効化。専用の赤い逆光と冷たい弱いキーライトへ切替。背後に低輝度の霧色を置いて輪郭を分離。細い端末コード表示、低振幅の信号ノイズ、断罪文を重ねる。低音の合成音は従来どおり音声有効化操作後に再生する。

## FPS空間と距離

- 保安通路に左右へ折れる3つの遮蔽壁。
- 原子炉中央に大型コンデンサー貨物。中央直進を塞ぎ、設備外周へ迂回する。
- 最終区画に左右交互の大型貨物壁。柱との隙間を確認し、右→左→中央へ進む。
- 中間のコンテナ、補強リブ、警告帯、搬入シャッターを追加。

共有する基準経路は **248.9m**。これは `FACILITY_ROUTE` のチェックポイントを結ぶ長さであり、最短経路の測定値ではない。全チェックポイントをプレイヤーの実衝突処理で通し、96体撃破と出口起動まで確認した。保安通路／原子炉／最終貨物区画のNavGraph接続も確認。グリッドは829ノードで、障害物半径を膨らませた線分検査により角の貫通を避ける。

## 遭遇と挟撃

各区画に4つの搬入口を設定。障害物・生存敵との重なりを避け、プレイヤーから5m以上離れた入口を選ぶ。遮蔽された入口を優先し、4回中後半2回は通過済み側の入口を優先する。背後入口が使えない場合は他の安全な入口へ戻す。全入口が使用中なら数を消費せず再試行し、近距離へ無理に出さない。

最初の常駐機以外は **1.4秒の入場予告**。シャッターが開き、警告音と前後のHUD通知を出し、その後、最後の0.4秒で機体が開口から前へ出る。入場中は射撃・被弾判定を開始しない。通常の索敵と初弾クールダウンもその後に始まる。空の床上へ突然実体化する方式を避けた。

テストでは、プレイヤーが蛇行通路の奥へ進んだ後、前方の敵を残したまま、通過済みの `(3.7, -13)` の搬入口に新たな敵が到着することを確認。全体の96体という進行条件は維持している。

## 色・光・HUD・画面効果

連続する赤青の線を短い器具へ分割。原子炉の大きな青い輪を金属構造へ変更し、炉は動く細い赤い導体パターンにした。青は主に武器・HUD・脱出誘導、赤は敵・炉・警告、面は黒と鋼色。プレイヤーのライトをスポット型へ変更し、標準品質で1024pxのソフトシャドウを使用。壁・貨物・敵が影を落とす。霧を増して奥行きを整理し、既存の蒸気・微粒子を併用する。

HUDは角の小さな透過パネルへ整理し、装備名と大きな読みやすい数値を分離。チャージは照準周囲にも円弧で表示。ヒットマーカーと被弾表示は維持。Bloom／Vignette／Film Grain／命中・被弾時だけの色収差も維持。強いグリッチは導入イベントに限定し、玉座の信号ノイズは微弱にした。低モーション設定では信号揺れを停止する。

## 検証と制約

Nodeの構文、site smoke、FPS simulation、lifecycle、weapon-state、glitch sequence、facilityを通過。本編25、武器15、終了・再開等16項目をブラウザで再実行して通過。加えて新経路の衝突検査・前後増援・全96体・脱出を検証した。全編進行は加速QAで、手動の全編プレイ時間を測ったものではない。

Chrome 157 / GTX 1080 Ti / 1440×1000 / DPR1 / 標準・2×MSAA・影あり。原子炉の敵12体、130フレームから最初10を除いた120サンプルで平均59.0fps、p95 16.9ms。末尾342 draw calls・138,756 triangles。遮蔽物の背後の敵を含む場面であり、全敵近接・連続爆発の最悪条件ではない。3回再入場のGPU資源数は毎回124 geometries / 16 texturesで増加なし。軽量品質では影を無効化する。

Antigravity 1.5.12 / Claude Sonnet 5.5 Mediumに遭遇設計の独立した机上レビューを依頼し、SUCCESSを確認。幅不足、入場とシャッターの同期、初弾猶予の指摘を照合した。別担当による玉座のコード提案と実コライダーの独立レビューも実施し、コンテナと重なった入口を修正した。採否・統合・描画確認はCodexが担当。

既知の制約：プロシージャルな造形。霧は距離フォグと軽量な描画で、光線追跡による体積散乱ではない。シャッターは入場の演出用で、独立した扉コライダーは置かない。敵AIは経路探索と射線を使う簡易AIで、本格的な戦術的カバー判断ではない。Safari／Firefox／低性能GPUの実機は未検証。グリフ残量計、両手、呼吸、自動/R交換、通常サイトは維持した。
